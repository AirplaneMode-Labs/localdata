Browser requirements

  • ? OPFS (navigator.storage.getDirectory, Chrome/Edge 86+, secure context)
  • ? IndexedDB
  • ? navigator.storage.estimate()
  • ? navigator.storage.persist()

All Airplane Mode Labs demos share one browser origin (airplanemode-labs.github.io): storage, quota, estimate() and persist() are shared between them. This demo writes only under airplanemode-localdata (namespace demo-fill for the quota fill).

What this demo does not do yet

  • Not yet: quantisation, compaction, encryption at rest, HNSW for queryChunks (the documents API stays a flat scan), a batched delete, and a measurement on an 8 GB laptop (not measured on 8 GB).
  • There is no compaction: deleting a document hides its chunks from every query but the bytes stay until the namespace is cleared. Nothing is encrypted at rest: any script on this origin, and anyone with this browser profile, can read what is stored.
  • The vector index is a flat scan unless a query asks for HNSW, and the documents are always a flat scan. HNSW is approximate: it can miss rows, and the page shows how many for its own 20,000 rows. The figures on this page are measured in this tab on this device; the README figures are from an Apple M5 Pro 48 GB and nothing here is an 8 GB figure.
  • A graph over very many exact copies of one vector is not promised to reach every copy: above 2m (32 at the default m) copies of one vector, or of vectors that are the same up to float noise in the low 12 mantissa bits of every component, the graph is degenerate and the exact flat scan answers instead (slower, never wrong). Wider tight clusters are not detected: on synthetic clusters with a relative spread of 1e-4 or more per component the graph alone returned scores below the flat scan's for some queries, so use flat when completeness matters. Detection depends on the data and the dimension: all-component float noise of about 1e-5 relative at dim 384 was not detected on a synthetic set. Nothing here is published: the npm scope and package name are not reserved, and nothing is signed with a real key.
  • The documents on this page are three synthetic, made-up documents with seeded vectors. There is no PDF reading, no text extraction and no embedding model here: that pipeline is the dockit demo.
  • The storage.* events reach only the list on this page: it registers an EventSink and renders what it receives. This page does not load the runtime, so the Airplane Mode DevTools panel does not show them; an app wires both by passing the same sink to createStore({ events }). The cost of events on a large workload has not been measured.
  • Not published: the npm scope and package name are not reserved; not tagged.
  • The key-value side has no cross-tab coordination: two tabs writing the same namespace can leave the accounting record stale until the next read repairs it. (The vector index and the documents take a Web Lock per namespace.)
  • Chrome under-reports IndexedDB usage in estimate(), so the browser figure and the SDK figure will not match on the indexeddb driver.
  • persist() may be refused without user engagement with the site; a refusal is shown as false, not as an error.
  • No service worker: offline after the first load is best effort (Chrome's HTTP cache), not guaranteed.

      Corrupt the graph truncates the graph record of the namespace demo-ann only (never the vectors); the next HNSW query refuses it, rebuilds it from the stored vectors and answers, and the events line shows both. "Make the graph an old-format file" rewrites that record as a graph of the first format (magic LDHNSW01, as 0.4.0-alpha.0 wrote it): the next HNSW query refuses it with the reason version and rebuilds it from the stored vectors. The SDK rebuilds a refused graph at most once per generation (a marker is stored beside the graph), so a second damage after a rebuild is refused and the index is dropped, not rebuilt: press Build to start again. Measured in this tab on this device; the README figures are from an Apple M5 Pro 48 GB; not measured on 8 GB.

      Documents

      Three synthetic documents of four chunks each (fixed made-up sentences with seeded vectors of dimension 384; no real document and no model), stored with putDocument in the namespace demo-docs and found again with queryChunks, which returns each chunk's text and the page it came from. The page uses its own store (OPFS, else IndexedDB) and closes it after every action, so Reload page followed by List documents is a genuine reopen.

        Delete hides a document's chunks in one commit; Clear namespace removes every file or record of the namespace, and the line above shows the browser's own count afterwards. Measured in this tab; not measured on 8 GB.

        Quota fill

        Writes 4 MiB chunks of random bytes (crypto.getRandomValues, synthetic) as keys fill-000001, fill-000002, ... under namespace demo-fill until the SDK soft quota or the browser reports quota_exceeded, Stop is pressed, or the ceiling is reached.
